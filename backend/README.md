# Baluarte backend

FastAPI service and background worker for Baluarte. Requires Python 3.12+.

## Development

```sh
python3.12 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'

uvicorn baluarte.main:app --reload   # http://127.0.0.1:8000/api/v1/health
pytest
ruff check . && ruff format --check .
mypy
```

The OpenAPI contract is generated by FastAPI at `/openapi.json`.

## Configuration

| Variable | Purpose |
|---|---|
| `BALUARTE_DATABASE_URL` | PostgreSQL URL without a password, e.g. `postgresql://baluarte@db:5432/baluarte?sslmode=require` |
| `BALUARTE_DATABASE_PASSWORD_FILE` | File containing the database password (mounted secret) |

OIDC sign-in is off until `BALUARTE_PUBLIC_URL`, `BALUARTE_OIDC_ISSUER` and `BALUARTE_OIDC_CLIENT_ID` are all set; until then sign-in and every protected endpoint answer 503. Setting only some of them, or mapping no groups, is a configuration error (logged, and the same 503). See [ADR-0006](../docs/architecture/ADR-0006-server-side-oidc-sessions.md).

| Variable | Default | Purpose |
|---|---|---|
| `BALUARTE_PUBLIC_URL` | | Browser-facing origin, e.g. `https://baluarte.example.internal`. Must be https unless the host is loopback. The redirect URI to register with the provider is this plus `/api/v1/auth/callback` |
| `BALUARTE_OIDC_ISSUER` | | Issuer URL (https); discovery is read from `/.well-known/openid-configuration` |
| `BALUARTE_OIDC_CLIENT_ID` | | Client ID registered with the provider |
| `BALUARTE_OIDC_CLIENT_SECRET_FILE` | | File holding the client secret. Omit for a public client (PKCE only) |
| `BALUARTE_OIDC_SCOPES` | `openid profile email` | Requested scopes; must include `openid`. Add the scope your provider needs to release groups |
| `BALUARTE_OIDC_ROLES_CLAIM` | `groups` | Claim listing the user's groups. Read from the ID token, or from userinfo if the ID token lacks it |
| `BALUARTE_OIDC_ADMIN_GROUPS`, `BALUARTE_OIDC_ANALYST_GROUPS`, `BALUARTE_OIDC_AUDITOR_GROUPS` | | Comma-separated groups granted each role; matching is exact and case-sensitive |
| `BALUARTE_SESSION_IDLE_MINUTES` | `60` | Session ends after this long without a request |
| `BALUARTE_SESSION_LIFETIME_MINUTES` | `480` | Session ends this long after sign-in regardless of activity |

To trust a private CA for the identity provider, point `SSL_CERT_FILE` at a CA bundle. Certificate verification cannot be disabled.

## Endpoints

- `GET /api/v1/health`: liveness. Does not touch the database.
- `GET /api/v1/ready`: 200 when PostgreSQL is reachable and migrated, otherwise 503 with which check failed. Errors are logged, not returned.
- `GET /api/v1/auth/login?return_to=/path`: redirects to the identity provider. `return_to` must be a same-origin path.
- `GET /api/v1/auth/callback`: the provider's redirect target. Sets the session cookie and redirects to `return_to`, or to `/sign-in?error=<code>` (`expired`, `provider_denied`, `provider_unavailable`, `not_authorized`, `sign_in_failed`).
- `GET /api/v1/auth/me`: the signed-in user, roles, permissions, session expiry and CSRF token; 401 without a session.
- `POST /api/v1/auth/logout`: revokes the session; needs the `X-CSRF-Token` header.

Every other endpoint requires a session (401 without one) and is checked against the permission matrix in [docs/SECURITY.md](../docs/SECURITY.md).

## Database and migrations

```sh
baluarte-migrate                                   # wait for the database, then upgrade to head
alembic revision --autogenerate -m "describe change" --rev-id 0003
```

Review every autogenerated revision; triggers and data migrations must be written by hand. See [docs/DATA_MODEL.md](../docs/DATA_MODEL.md).

Database tests need a PostgreSQL server where the test user can create databases. Each test creates and drops its own database:

```sh
docker run -d --name baluarte-testdb -e POSTGRES_USER=baluarte -e POSTGRES_PASSWORD=devonly \
  -p 127.0.0.1:55432:5432 postgres:17-alpine
export BALUARTE_TEST_DATABASE_URL=postgresql://baluarte:devonly@127.0.0.1:55432/postgres
pytest
```

Without `BALUARTE_TEST_DATABASE_URL` the database tests are skipped; CI sets `BALUARTE_REQUIRE_DB_TESTS=1` so they fail instead.
